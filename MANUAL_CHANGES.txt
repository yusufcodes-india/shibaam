SHIBAAM Collection Portal — ALL MANUAL CHANGES (step by step)
============================================================
Do these in order. Each step says FILE + LINE HINT + what to change.

------------------------------------------------------------
STEP 1 — Deploy the backend (Google Apps Script)
------------------------------------------------------------
1a. Open your Google Sheet -> Extensions -> Apps Script.
1b. Delete everything in Code.gs, paste the full contents of:
      /shibaam/files/Code.gs   (1023 lines)
1c. In the Apps Script toolbar, select function: setupSpreadsheet
    Click Run. Accept all authorization prompts (Spreadsheet + Drive).
    This creates 9 tabs, freezes row 1, seeds Settings + 4 AdminKeys.
1d. Deploy -> New deployment -> type Web App:
      Execute as: Me
      Who has access: Anyone
1e. Click Deploy. Copy the Web App URL. It looks like:
      https://script.google.com/macros/s/AKfycb.../exec
    KEEP THIS URL — you need it in Step 2.

------------------------------------------------------------
STEP 2 — Point the measurement page at your backend
------------------------------------------------------------
FILE: admin-measurement-add.html  (line ~450)
FIND:
    const APPS_SCRIPT_URL = 'https://script.google.com/macros/s/YOUR_SCRIPT_ID/exec';
REPLACE YOUR_SCRIPT_ID with your real deployment ID from Step 1e.
Example:
    const APPS_SCRIPT_URL = 'https://script.google.com/macros/s/AKfycb.../exec';

NOTE: Until you do this, the page runs in LOCAL DEMO mode
(localStorage only). After you set the URL, saves also go to
your Google Sheet + real Drive folders are created.

STEP 5 — Match AdminKeys between backend and demo login
------------------------------------------------------------
Code.gs seeds these 4 keys on setup (AdminKeys tab):
    SHBM-SUPER-2024 / SHBM-ADMIN-2024 / SHBM-ADMIN-001 / SHBM-ADMIN-002
admin-login.html VALID_KEYS (line ~219) contains the SAME 4 keys
for offline demo mode.
- To ADD a staff member: add the key in BOTH places
  (AdminKeys sheet row + VALID_KEYS object), or better: wire
  admin-login.html to call api('login_admin') once backend is live.
- To DISABLE a key: set active=FALSE in the AdminKeys sheet
  (backend refuses it) AND remove it from VALID_KEYS.

------------------------------------------------------------
STEP 6 — Sales team names (2 places, keep in sync)
------------------------------------------------------------
DEFAULT list lives in:
  - Code.gs seedSettings()  (lines ~167-172, used by backend)
  - admin-settings.html      (line ~431, offline default)
  - admin-new-job.html / customer-shop-video.html load from
    localStorage key shibaam_sales_team (written by admin-settings page).
After going live, edit the team ONLY in admin-settings.html and
click save — it writes localStorage (and backend once wired).

------------------------------------------------------------
STEP 7 — Demo data you may want to clear
------------------------------------------------------------
These pages ship with hardcoded demo rows for offline testing.
They are REPLACED automatically once real localStorage/backend
data exists, but you can delete them to start empty:
  - admin-jobs.html          DEFAULT_JOBS array (SHBM-4600..4603)
  - admin-measurements.html  DEFAULT_MEASUREMENTS array (4 rows)
  - admin-workers.html       workersData array (5 rows)
  - admin-customers.html     customers array (4 rows)
  - admin-delivery.html      deliveriesData array (5 rows)
  - admin-queries.html       DEFAULT_QUERIES array (4 rows)
  - customer-orders.html     DEMO_ORDERS object (SHBM-4600..4602)
To clear at runtime instead: open browser console and run
  localStorage.clear()
then reload.
